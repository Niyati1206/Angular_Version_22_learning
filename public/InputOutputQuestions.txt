# Angular Practice: `@Input()` and `@Output()`

A collection of hands-on Angular exercises to practice parent-child communication using `@Input()`, `@Output()`, `EventEmitter`, signals of data flow, and event binding.

## Part 1: `@Input()` — Parent to Child Communication

### Level 1 — Q1. User Profile

**Task:** Create a reusable child component called `UserProfileComponent`.

**Requirements:**
- The parent component has a variable `username` initialized to `'Niyati'`.
- Pass `username` from the parent to the child using `@Input()`.
- The child displays `Welcome, Niyati!`.
- Change the parent's username to `'Priya'` and verify that the child displays `Welcome, Priya!`.

**Concepts:** Basic `@Input()`, property binding, interpolation.

### Level 2 — Q2. Product Details

**Task:** Create a child component called `ProductCardComponent`.

**Requirements:**
- The parent defines three variables:
  - `productName = 'Laptop'`
  - `price = 55000`
  - `inStock = true`
- Pass all three values to the child using separate `@Input()` properties.
- The child displays the product name, price, and stock status.
- Display `Available` when `inStock` is `true`; otherwise, display `Out of stock`.

**Concepts:** Multiple inputs, string/number/boolean types, conditional rendering.

### Level 3 — Q3. Student Marks

**Task:** Create a child component called `StudentResultComponent`.

**Requirements:**
- The parent contains an array of students, each with a `name` and `marks` property.
- Use `@for` in the parent template to render one child component per student.
- Pass each student's name and marks to the child using `@Input()`.
- The child displays the student's name, marks, and result.
- Students with marks of 35 or above pass; students with marks below 35 fail.

**Example data:**

| Name | Marks | Result |
|---|---:|---|
| Niyati | 78 | Pass |
| Priya | 28 | Fail |
| Rahul | 45 | Pass |

**Concepts:** `@Input()`, arrays of objects, `@for`, conditional rendering.

### Level 4 — Q4. Reusable Counter Display

**Task:** Create a child component called `CounterDisplayComponent`.

**Requirements:**
- The parent has a variable `count`, initially set to `0`.
- Add buttons in the parent to increase and decrease `count`.
- Pass the current count to the child using `@Input()`.
- The child displays the current count and a status message based on these rules:
  - Count greater than 10: `High`
  - Count from 1 to 10: `Normal`
  - Count of 0 or below: `Low`

**Concepts:** Reactive parent data, input updates, conditional logic, reusable components.

## Part 2: `@Output()` — Child to Parent Communication

### Level 1 — Q5. Greeting Button

**Task:** Create a child component called `GreetingButtonComponent`.

**Requirements:**
- The child contains a button labelled `Say Hello`.
- When clicked, the child emits the string `'Hello Parent!'` using `@Output()`.
- The parent listens for the event and stores the received message in a variable.
- The parent displays the message after the button is clicked.

**Concepts:** `EventEmitter<string>`, `.emit()`, `$event`, event binding.

### Level 2 — Q6. Add to Cart

**Task:** Create a child component called `AddToCartComponent`.

**Requirements:**
- The parent has a product name set to `'Headphones'`.
- Pass the product name to the child using `@Input()`.
- The child displays the product name and an `Add to Cart` button.
- When clicked, the child emits the product name to the parent using `@Output()`.
- The parent stores the selected product in an array called `cart`.
- The parent displays all products currently in the cart.

**Concepts:** Combining `@Input()` and `@Output()`, passing data from child to parent, array updates.

### Level 3 — Q7. Child Counter Controls

**Task:** Create a child component called `CounterControlsComponent`.

**Requirements:**
- The child has `+1` and `-1` buttons.
- Clicking either button emits the corresponding number, `1` or `-1`, to the parent.
- The parent receives the emitted number and updates its own `count`.
- The parent displays the current count.
- The child must not directly modify the parent's count.

**Concepts:** Typed events, numeric payloads, parent-owned state.

### Level 4 — Q8. Task Manager

**Task:** Create a child component called `TaskItemComponent`.

**Requirements:**
- The parent has the following task list:
  - `Study Angular`
  - `Practice TypeScript`
  - `Revise Signals`
- Use `@for` in the parent template to render one child component per task.
- Each child receives its task name through `@Input()`.
- Each child has a `Complete` button.
- When clicked, the child emits its task name to the parent.
- The parent removes the completed task from its list.

**Concepts:** Combining `@Input()` and `@Output()`, list rendering, event payloads, array updates.

## Part 3: Combined Practice — `@Input()` + `@Output()`

### Bonus — Q9. Like Button

**Task:** Create a child component called `LikeButtonComponent`.

**Requirements:**
1. The child component has a button labelled `Like 👍`.
2. When clicked, the child emits the string `'You liked this post!'` to the parent using `@Output()`.
3. The parent listens for the event and stores the received message in a variable called `message`.
4. The parent displays the message after the button is clicked.

**Concepts:** `@Output()`, `EventEmitter<string>`, `.emit()`, `$event`, event binding, parent-owned state.

---

## Learning Goals

By completing these exercises, you will practise:

- Passing data from parent to child using `@Input()`.
- Sending events and data from child to parent using `@Output()`.
- Using `EventEmitter<T>` with appropriate types.
- Handling emitted values with `$event`.
- Rendering lists using Angular's `@for` block.
- Implementing conditional rendering and updating arrays.
- Building reusable components with clear responsibilities.
